# 참고 서비스 분석 (reference audit)

- 분석 대상: `riseyoo1-alt/one-qr-service` (GitHub 공개 저장소) 및 해당 저장소의 GitHub Pages 배포본
- 분석일: 2026-09-18
- 분석 목적: 기능·정보구조 파악 및 개선점 도출. **소스코드·이미지·문구를 복제하지 않음.**

## 0. 라이선스 확인 결과

저장소 루트에 `LICENSE` 파일이 **없다.** 명시적 라이선스가 없는 저작물은 기본적으로 저작권이 유보되므로,
본 프로젝트는 참고 저장소의 **코드·CSS·이미지(base64 내장 샘플 서식 스캔 이미지 포함)·문구를 일절 복사하지 않고**
기능 목록과 정보구조만 참고하여 전부 새로 작성하였다.

참고 저장소 파일 구성 (clone 후 확인):

| 파일 | 크기 | 비고 |
| --- | --- | --- |
| `index.html` | 약 2.74 MB | 서비스 전체(HTML+CSS+JS+주소DB+base64 이미지)가 단일 파일 |
| `serbes.html` | 약 2.74 MB | `index.html`과 거의 동일한 사본 |
| `test.html` | 약 2.73 MB | 역시 거의 동일한 사본 |
| `내땅위치안내_시작화면.html` | 약 0.09 MB | 별도 시작화면 |

빌드 도구, 패키지 매니페스트, 테스트, CI 설정, 문서가 모두 없다.

## 1. 기능 및 정보구조

참고 서비스는 `여주시` 대상 `One-QR 민원 편의 서비스`이며, 단일 페이지 안에서 패널을 전환하는 구조다.

주요 메뉴 5종(내비게이션 카드):

1. 통합발급 서식 샘플 — 서식 스캔 이미지 + 항목 주석
2. 용어 해설 — 지적·건축 용어 설명 팝업
3. 주소검색 — 지번/도로명 조회
4. 면적계산기 — ㎡ ↔ 평 환산
5. 정부24 문서 확인 — 외부 링크 모음

부가 기능:

- 상단 음성검색 바 (Web Speech API `SpeechRecognition` + `speechSynthesis`)
- 음성인식 실패 시 텍스트 입력 대체 행
- 용어 클릭 시 중앙 모달(`.tooltip`)과 오버레이 표시

## 2. 확인된 문제점

### 2.1 콘텐츠 정확성 (가장 중요)

| 항목 | 참고 서비스의 서술 | 문제 |
| --- | --- | --- |
| 토지등급 | "토지 가치 순위. 1등급이 가장 비싸고 숫자 클수록 저렴합니다." (`tips`, `voiceTerms` 두 곳에 중복 서술) | 현행 공적장부의 토지등급 표기를 단순 가격 순위로 단정하는 설명이다. 공식 근거가 확인되지 않음. |
| 전입세대확인서 | `정부24 문서 확인` 카드 설명에 "등·초본·전입세대확인서·건축물대장·인감증명서 **온라인 확인**"으로 묶어 표기 | 전입세대확인서는 정부24 민원안내상 신청방법이 **방문**으로 안내된다. 온라인 발급 가능 서류와 한 문장에 묶으면 오인 가능. |
| 수수료·처리기간·준비서류 | 서식 샘플 주석 형태로만 존재하고, 출처 URL·확인일·검토상태가 전혀 없음 | 갱신 시점과 근거를 추적할 수 없다. |
| 면적 환산 상수 | `var PY=3.30579;`, 화면 문구 "1평 = 3.30579㎡ (국가 공식 환산 기준)" | 값 자체는 근사값으로 무리가 없으나 "국가 공식 환산 기준"이라는 표현의 근거가 제시되지 않았다. |

→ 본 프로젝트 대응: `docs/content-review-checklist.md` 참조. 토지등급은 **설명을 싣지 않고 `담당부서 확인 필요`로 표시**하며,
전입세대확인서는 **`방문 신청만 가능`으로 분리 표기**한다.

### 2.2 주소검색 로직

참고 구현(`liveSearch`)의 매칭 조건은 다음과 같다.

```js
else if (jibun.includes(q)) match = true;        // 지번 문자열 부분일치
else if (bno === q) match = true;                 // 건물번호 완전일치
else if ((road + ' ' + bno).includes(q)) match = true;
else if ((dong + ' ' + jibun).includes(q)) match = true;
```

문제:

- **지번을 문자열 부분일치로 검색한다.** `12` 입력 시 `12`, `12-3`, `112`, `312-1`, `1200` 이 모두 걸린다.
- **본번과 부번이 구조적으로 분리되어 있지 않다.** `DB` 배열이 `[동코드, "228-2", 도로코드, "135-5", 건물명]` 형태의 문자열이다.
- **AND 조건이 없다.** 지역명과 숫자를 함께 입력해도 `else if` 사슬에서 먼저 참이 되는 조건 하나만으로 결과가 들어간다.
- 단어 매칭이 `wHit >= Math.ceil(words.length * 0.5)`, 즉 **절반만 맞아도 통과**한다.
- 결과를 `max = 50`에서 자르고 정렬·순위가 없어, 정확한 결과가 잘려 나갈 수 있다.
- 결과가 많을 때 추가 조건을 요청하지 않고 "(최대 50건 표시)"만 덧붙인다.
- 폴백 검색 `searchDB()`는 검색어를 2글자씩 잘라 부분일치시키는 단계가 있어 무관한 결과를 반환할 여지가 크다.

### 2.3 데이터·아키텍처

- 주소 DB(`DB`, `DN`, `RD`)가 `index.html` 안에 인라인되어 있다. 최장 한 줄이 약 868 KB다.
- 서식 샘플 스캔 이미지가 **base64로 HTML에 내장**되어 있어 문서 하나가 수백 KB를 차지한다.
- 초기 로드 시 2.74 MB HTML 전체를 파싱해야 하며, 캐싱·부분 갱신이 불가능하다.
- 화면 코드와 콘텐츠가 분리되어 있지 않다.
- `index.html` / `serbes.html` / `test.html` 3개 사본이 거의 동일해 콘텐츠 갱신 시 동기화 누락 위험이 크다.

### 2.4 접근성 (KWCAG 2.2 관점)

- 내비게이션이 `<div class="nav-card" onclick="sp('gov')">` 형태다. `button`/`a`가 아니므로 키보드 포커스·엔터 실행·역할 전달이 되지 않는다.
- 주소 검색결과 카드도 `<div onclick="showVResult(...)">`이다.
- 입력 요소에 연결된 `<label>`이 없다(`placeholder`만 사용).
- 검색결과 영역에 `aria-live`가 없어 스크린리더가 결과 변경을 알 수 없다.
- 모달(`.tooltip`)에 `role="dialog"`, 포커스 트랩, 닫은 뒤 포커스 복귀가 없다.
- `:focus-visible` 스타일이 없고 `-webkit-tap-highlight-color:transparent`로 시각 피드백을 줄였다.
- 본문 바로가기 링크가 없다.
- 상태 표시가 색상 중심이다(`.callout.g/.t/.p/.a`).
- `prefers-reduced-motion` 대응이 없고 `transition`/`transform` 애니메이션이 상시 동작한다.
- 제목 구조가 `h1` → `h2`만 있고 패널 제목(`.pt`)은 `div`다.
- `meta viewport`에 `maximum-scale=5.0`이 지정되어 확대 한도가 제한된다.

### 2.5 보안·프라이버시

- 검색결과를 `box.innerHTML = html` 로 문자열 연결해 주입한다. 데이터가 정적이라 현재는 동작하지만, 데이터 교체 시 XSS 경로가 된다.
- 인라인 `onclick`/`onmouseover` 핸들러가 다수라 CSP 적용이 불가능하다.
- 외부 폰트 CDN(`fonts.googleapis.com`)에 의존한다. 폐쇄망·내부망 배포 시 깨지고, 방문자 IP가 외부로 전달된다.
- 외부 링크의 `rel="noopener noreferrer"` 적용이 일관되지 않다.
- 전역 상태를 `window._lsResults`에 보관한다.

### 2.6 운영 구조

- GitHub Pages 자체가 서비스 운영 환경이다. 개발용/공식 배포용 구분이 없다.
- `robots.txt`, `noindex`가 없어 개발본이 검색엔진에 수집될 수 있다.
- 빌드·검증·패키징 스크립트가 없어 전달본을 재현 가능하게 만들 수 없다.

## 3. 본 프로젝트에서의 대응 요약

| 참고 서비스 문제 | 본 프로젝트 대응 |
| --- | --- |
| 단일 2.7MB HTML | Vite + TypeScript, 화면/데이터/로직 분리, 주소 인덱스는 별도 JSON을 런타임 fetch |
| 부분일치 주소검색 | 지역명 AND 숫자 조건, 본번/부번 구조 분리, 문자열 부분일치 금지 (`tests/address-search.test.ts`) |
| 근거 없는 행정정보 | `sourceUrl` + `verifiedAt` + `reviewStatus` 필수, `scripts/validate-content.mjs`로 빌드 차단 |
| 토지등급 오설명 | 해당 설명 미게시, `담당부서 확인 필요`로 표기 |
| 전입세대확인서 온라인 오인 | `visit-only`(방문 신청만 가능)로 분리 표기 |
| div + onclick | 모든 조작 요소를 `button`/`a`로 구현, 인라인 핸들러 없음 |
| innerHTML 주입 | `textContent` + `createElement`만 사용 |
| 외부 폰트 CDN | 시스템 한글 글꼴 스택 사용, 외부 요청 0건 |
| GitHub Pages가 운영환경 | `build:preview`(개발·검토용) / `build:official`(충주시 서버용) 분리, `verify-official-build.mjs`로 검증 |
| 여주시 자산 | 사용하지 않음. 공식 빌드 검증 스크립트가 `여주`, `github.io`, `riseyoo1-alt` 문자열을 탐지해 실패시킴 |

## 4. 참고하지 않은 것

- 서식 스캔 이미지(등·초본 위임장, 전입세대확인서 신청서, 인감 위임장, 토지대장, 대지권등록부, 건축물대장,
  지적도 등본, 경계점좌표등록부, 토지이용계획확인서 등) — 저작권·개인정보 확인 불가로 **일절 사용하지 않는다.**
- 참고 서비스의 CSS 토큰, 클래스명, 레이아웃 코드.
- 참고 서비스의 여주시 주소 데이터(`DB`/`DN`/`RD`).
- 참고 서비스의 용어 설명 문구.
